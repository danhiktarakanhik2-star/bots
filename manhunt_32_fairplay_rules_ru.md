# 32 — Честная игра, правила и границы информации

Тактический бот должен быть сильным внутри правил, а не выигрывать благодаря скрытому доступу. До матча запиши правила, разрешённые наблюдения, действия и условия завершения. Если правил нет, уточни их у хозяина сервера.

## 1. Иерархия правил

1. Правила владельца/организатора матча.
2. Серверные ограничения и античит.
3. Явные соглашения игроков о форматах/эксплойтах.
4. Внутренняя policy бота, более строгая чем разрешённое, если нужно.

Если две установки конфликтуют, не выбирай тихо более выгодную. Спроси или выбери безопасное действие до уточнения.

## 2. Список разрешённых сведений

```text
разрешено: собственная позиция/инвентарь; видимые сущности; игровой чат;
           обычный compass или tracking plugin, если он всем доступен
запрещено, пока явно не разрешено: spectator-camera; скрытые координаты;
           seed/карта; чужой инвентарь; команды/админ-логи; метаданные записи
```

Перечень адаптировать под сервер. Система prompt должна получать только разрешённые поля, чтобы модели было невозможно «случайно» использовать hidden state.

## 3. Правила старта и завершения

Зафиксировать: grace period, разрешён ли урон до старта, что считается смертью, можно ли hunter’ам возрождаться, что означает победа, что делать при disconnect/лаг-пике, как разрешается ничья. Проверять событие победы по игровому API, а не по эмоции или спорной реплике.

## 4. Стратегии с отдельным разрешением

Portal camping, traps, block breaking, bed/crystal tactics, скрытые координаты и команды сервера могут быть разрешены в одном матче и запрещены в другом. Пометка из видео или вики не заменяет user ruleset. Для каждой тактики добавить `allowed`, `blocked`, `unknown`; при `unknown` агент выбирает fallback.

## 5. Наблюдение и честность

Бот не должен сообщать, что «видит» игрока, если получает только компас. Не использовать ложные координаты от одной модели как истину. Если пользователь в чате врёт о маршруте, это не обновляет игровую карту до подтверждения. Обратно, использовать только доступные игровые сигналы, а не тайные server logs.

## 6. Антиэксплойт и админ-инструменты

Админ-команда допустима только при явном согласии организатора и одинаковом доступе/правиле для сторон. Не прятать вмешательство, не использовать exploit, crash, x-ray, kill command или незаконный teleport. Для тестового стенда можно использовать команды, но такие результаты не считать fair-play матчем.

## 7. Правила Dream vs ваши правила

Официальный Dream ролик о производстве Manhunt описывает специальные решения их серии, например выбор стартового seed и ограничения на часть стратегий. Это полезный контекст, но бот должен иметь отдельный `ruleset_id` вашего сервера: [официальный источник](https://www.youtube.com/watch?v=km1IlBAZJH0). Не переносить автоматом их денежные стимулы, отбор записей, reset’ы или монтажные условия в реальную игру.

## 8. Контрольный список запуска

- [ ] Роли игроков перечислены.
- [ ] Редакция и версия известны.
- [ ] Tracking/compass определён.
- [ ] Respawn/жизни определены.
- [ ] Portal rules/ловушки определены.
- [ ] Конкретное win condition согласовано.
- [ ] API не раскрывает hidden state.
- [ ] Боты знают, как остановить матч по команде хозяина.
